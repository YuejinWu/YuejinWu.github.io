进程&线程&调度

第二部分：进程

1. 进程概述

1.1 主题

  • 虚拟进程抽象
  • 地址空间概念
  • 进程是如何创建的
  • 进程与操作系统之间的交互

2. CPU、内存和磁盘的限制

2.1 现状（简化模型）

  • CPU 执行无穷无尽的指令流（在内存中）
  • 所有系统内存都在连续的物理地址空间中
  • 磁盘是一组有限的块
  • 所有指令都在特权模式下执行

2.2 操作系统的任务

为了处理并发程序，操作系统必须分离不同程序的执行，让程序产生错觉，以为每个程序都是唯一运行的程序。虚拟进程抽象提供了这种错觉。

3. 运行多个程序

3.1 多道编程

  • 目的：提高 CPU 的利用率
  • I/O 密集型程序大部分时间都在等待 I/O，让 CPU 忙于处理其他任务可以提高效率

3.2 多道编程与时间共享

  • 多道编程：在一个物理地址空间中容纳多个进程

    • 每个进程都可以是 I/O 密集型或 CPU 密集型
    • 最好混合使用 I/O 密集型与 CPU 密集型进程
    • 目标是提高 CPU 利用率
    • 调度程序决定执行哪个进程

  • 时间共享（多任务）：在进程间快速来回切换——称为上下文切换

    • 目的是减少用户与计算机交互时的延迟

4. 进程抽象

4.1 程序与进程

  • 程序：由静态代码和数据组成，例如磁盘上的静态代码和数据
  • 进程：程序的运行实例。在任何时候，一个程序都可能有 0 个或多个运行实例

4.2 进程定义

进程是运行时上下文视图中的一个执行流。执行流是执行指令的序列（即“控制线程”）。运行时上下文包括执行指令能够影响或受到影响的所有内容（如寄存器、地址空间、持久数据（如文件））。

注意：运行时上下文有两个方面，即进程视图和操作系统视图。操作系统跟踪地址空间和持久性。

5. 进程的组成

5.1 执行上下文（环境）

程序运行时可以读取或更新的内容。

5.2 组成部分

  1. 内存：进程可寻址的内存称为其地址空间
  2. 寄存器：程序计数器（PC）、堆栈指针（SP）等
  3. I/O 信息：当前打开的文件列表

6. 进程地址空间

进程可访问的一组内存段称为进程的地址空间。

6.1 内存段

  • 文本：程序代码（通常只读）
  • 数据：全局变量和常量
  • 堆栈：每一帧都包含参数、局部变量和函数的返回地址
  • 堆：动态分配的内存，例如在 C 语言中调用 malloc()

6.2 虚拟地址空间布局

问题：为什么堆栈和堆的增长方向相反？
答案：这样可以在动态分配时最大限度地利用地址空间，避免堆和堆栈过早碰撞。

7. 从程序创建进程

7.1 过程

  1. 程序（代码和数据）位于磁盘上
  2. 操作系统创建进程时，将代码和数据加载到内存
  3. 分配堆和栈空间，形成进程的地址空间

8. 为什么使用进程抽象？

  • 允许在同一物理地址空间执行多个程序
  • 虚拟化 CPU：多个独立进程同时在一台物理机上运行的错觉
  • 实际上，每个 CPU 在任何时候都只能有一个进程处于活动状态

9. 术语比较

  • 程序：磁盘上的应用程序，由代码和数据组成
  • 进程：一个程序的运行实例。进程开始时只有一个执行线程和一个地址空间
  • 线程：一个进程可以在同一地址空间中启动多个执行线程。每个线程都有自己的堆栈，但它们共享全局数据、代码和堆

10. CPU 虚拟化

10.1 目标

让每个进程都有独占 CPU 的错觉

10.2 现实

CPU 是所有进程共享的资源

10.3 方法

  • 时间共享：独占使用，一次一个
  • 空间共享：每个进程一直使用一小块空间

10.4 不同资源的策略

  • CPU：时间共享，不同任务交替使用
  • 内存：空间共享
  • 磁盘：空间共享

11. 操作系统提供的进程抽象

  • 当用户执行程序时，操作系统会创建一个进程
  • 操作系统将 CPU 分时分配给多个进程
  • 操作系统调度程序从可执行进程中挑选一个进程运行
    • 调度程序必须保存进程列表
    • 调度器必须为调度策略保存元数据

12. 策略与机制的区别

  • 策略：运行哪个进程
  • 机制：如何从一个进程切换到另一个进程

策略和机制的区别实现了模块化。调度策略独立于上下文切换功能。

13. 进程创建

  1. 操作系统分配内部数据结构
  2. 操作系统分配地址空间
    • 从磁盘加载代码和数据
    • 创建运行堆栈和堆
  3. 操作系统打开基本文件（STDIN、STDOUT、STDERR）
  4. 操作系统初始化 CPU 寄存器

14. 进程状态

  • 运行：当前进程正在执行
  • 就绪：该进程已准备就绪，可以执行（当策略决定执行时，该进程将被调度）
  • 阻塞：该进程处于暂停状态（例如，等待某些操作；操作完成后，操作系统将解除对它的阻塞）
  • 新建：正在创建该进程（确保它不会被调度）
  • 终止：此进程已终止（例如，如果父进程尚未读出返回值）

15. 进程状态转换

16. 空闲进程

如果所有进程都被阻塞，应该调度哪个进程？

空闲进程：现代内核使用低优先级的空闲进程，如果没有其他进程准备就绪，它就会被调度并执行。空闲进程从不阻塞或执行任何 I/O。

作用：

  • 保证始终至少有一个进程可以运行
  • 简化调度逻辑

17. 操作系统数据结构

17.1 进程控制块（PCB）

操作系统维护活动进程的数据结构（数组/列表）。每个进程的信息都存储在一个进程控制块（Linux 上称为 task_struct）中，包含：

  • 进程标识符（PID）
  • 进程状态（如就绪）
  • 父进程指针
  • CPU 上下文（如果进程未运行）
  • 地址空间指针
  • 打开文件列表指针（文件描述符）

17.2 PCB 在上下文切换中的作用

18. 上下文切换

18.1 定义

保存进程的所有状态，允许进程暂时中止，随后从相同点恢复。然后，另一个进程可以通过恢复其保存的状态来恢复。

18.2 开销

执行上下文切换所需的时间是希望最小化的“开销”。

19. 程序/进程/线程的区别

  • 程序：由磁盘上的可执行文件组成，包含启动进程的所有信息
  • 进程：程序的运行实例；数据段和堆栈段已初始化
  • 线程：一个进程可以在同一地址空间拥有多个线程（操作相同的数据）

19.1 进程与线程的具体区别

  • 在某些操作系统（如 Linux）中，线程是“轻量级进程”（LWP）
  • 线程由堆栈和寄存器状态（堆栈指针、代码指针、其他寄存器）组成
  • 每个进程都有一个或多个线程

关键区别：

  • 读取地址 0xc0f3 的两个进程可能会读到不同的值
  • 同一进程中的两个线程会读取相同的值

20. 请求操作系统服务

  • 进程可以通过系统调用 API 请求服务
  • 系统调用会将执行权移交给操作系统（操作系统通常以更高的权限运行，可以进行特权操作）
  • 敏感操作（如硬件访问、原始内存访问）需要（执行）权限
  • 某些系统调用（如“读”、“写”）可能会导致进程阻塞，从而允许操作系统调度其他进程
  • 库（libc）隐藏了系统调用的复杂性，以普通函数调用的形式输出操作系统功能

21. 进程 API

进程 API 使进程能通过一组系统调用来控制自身和其他进程：

  • getpid()：获取进程 ID，每个进程都有一个唯一的 PID
  • fork()：创建一个新的子进程（进程的副本）
  • exec()：执行一个新程序
  • exit()：终止当前进程
  • wait()：阻塞父进程，直到子进程终止

21.1 fork()：创建新进程

  • 操作系统为新进程（子进程）分配数据结构
  • 操作系统复制调用者（父进程）的地址空间
  • 子进程准备就绪，并被添加到进程列表中
  • fork() 返回父进程/子进程的不同值（子进程返回 0，父进程返回子进程 PID）
  • 父进程和子进程在各自独立的地址空间副本中继续执行

21.2 fork() 示例

21.3 exec()：执行（新）程序

  • exec() 替换地址空间，从磁盘加载新程序
  • 程序可以传递命令行参数和环境
  • 旧的地址空间/状态会被销毁，但 STDIN、STDOUT、STDERR 除外，它们会被保留，允许父进程重定向子进程的输出

21.4 为什么需要 fork() 和 exec()？

假设用户想启动一个不同的程序。为此，操作系统需要创建一个新进程，并创建一个新的地址空间来加载程序。

我们分而治之：

  • fork()：创建一个新进程，并拷贝该地址空间
  • exec()：为程序创建一个新的地址空间
  • clone()：为该地址空间添加一个（执行）线程

21.5 wait()：等待子进程

  • 子进程与父进程绑定
  • exit(int retval) 需要一个返回值参数
  • 父进程可以 wait() 等待子进程终止，并读取子进程的返回值

21.6 使用 fork() 创建进程小结

22. 确保高效执行

22.1 问题

进程在 CPU 上直接执行指令，但存在以下问题：

  • 进程可能会做一些非法的事情（读/写不属于进程的内存，直接访问硬件）
  • 进程可能永远运行（操作系统必须保持控制）
  • 进程可能做一些缓慢的事情，如 I/O（操作系统可能想切换到另一个进程）

22.2 解决方案

操作系统在硬件的帮助下保持一定的控制：

  • 维护定时器，定期拦截执行
  • 进程不能执行直接访问硬件的特权指令

23. 进程隔离

23.1 策略

  • 在大多数操作系统中，进程都是：

    • 相互隔离
    • 与操作系统隔离

  • 隔离是安全的核心要求：

    • 限制进程的错误
    • 实现权限隔离
    • 实现分隔（将复杂系统分成独立的故障域）

23.2 机制

  • 虚拟内存：每个进程有一个（虚拟）地址空间
  • 不同的执行模式：操作系统在较高权限下执行
    • 进程在用户模式下执行（x86 的环 3）
    • 操作系统在系统/内核模式下执行（x86 的环 0）

24. 总结

  • 进程是一个纯粹的虚拟概念
  • 将策略和机制分开可实现模块化
  • 操作系统是服务器，响应硬件和进程的需求
  • 进程与操作系统/其他进程隔离
    • 进程不能直接访问设备
    • 进程在虚拟内存中运行
    • 操作系统通过系统调用提供功能
  • 进程由地址空间、相关内核状态（如打开的文件、网络通道）和一个或多个执行线程组成

25. 实践命令（Linux）

  • ps -ef | grep [进程名]：查看进程信息
  • top -p [pid]：查看特定进程的动态信息
  • top -H -p [pid]：查看特定进程的线程信息
  • ps xh：查看所有进程（无标题）
  • ps -mp [pid]：查看特定进程的线程详细信息
  • pstree：以树状结构显示进程

第三部分：线程

1. 线程概述

1.1 进程与线程的区别

  • 进程：最小资源分配单位
  • 线程：最小执行单元

类比：一个家庭包含配偶，家庭可以买房买车（资源）。配偶住在一个房子里（相同的地址空间），但可以有各自不同的任务。

2. 动机

  • 大多数现代应用程序都是多线程的
  • 线程在应用程序内运行
  • 应用程序的多个任务可由独立线程执行，例如 WPS 或 MS Office：
    • 更新显示
    • 获取输入数据
    • 拼写检查
    • 自动备份
  • 进程创建重量级，线程创建轻量级
  • 可简化代码，提高效率
  • 内核通常是多线程的

6. 线程调度状态

线程调度器在物理 CPU 上复用线程。调度器根据线程状态决定运行哪个线程。

6.1 线程状态

  • 运行中：线程正在使用处理器
  • 阻塞：线程正在等待输入
  • 就绪：线程已准备好运行
  • 已退出：线程已退出但未销毁

7. 线程调度原语

  • yield()：当前线程让出 CPU
    • 状态变化：运行 → 就绪
  • sleep()：当前线程因故阻塞
    • 状态变化：运行 → 阻塞（例如，发送到满缓冲区）
  • wakeup()：另一个线程唤醒一个线程
    • 状态改变：阻塞 → 就绪（例如，缓冲区空间可用）

8. 多线程的优点

  • 响应性：当部分进程被阻塞时，可允许继续执行，这对用户界面尤为重要
  • 资源共享：线程共享进程资源，比共享内存或消息传递更简单
  • 经济性：比创建进程便宜，线程切换的开销比上下文切换低
  • 可扩展性：线程可利用多处理器架构的优势

9. 并发与并行

9.1 并发

  • 单核系统上的并发执行：多个线程交替执行，同一时间只有一个线程运行

9.2 并行

  • 多核系统上的并行执行：多个线程同时在不同的核心上执行

10. 多核编程

10.1 挑战

多核或多处理器系统给程序员带来压力，挑战包括：

  • 划分活动
  • 平衡：程序员要确保各任务执行同等价值的工作
  • 数据分割
  • 多个任务之间的数据依赖性
  • 测试和调试

10.2 并行与并发

  • 并行：系统可同时执行多个任务
  • 并发：支持多个任务同时进行。单处理器/内核，调度程序提供并发性

10.3 并行类型

  • 数据并行：将相同数据的子集分配给多个内核，每个内核上的操作相同
  • 任务并行：在多个内核上分配线程，每个线程执行独特的操作
  • 在大多数情况下，应用程序会混合使用这两种策略

10.4 硬件支持

随着线程数量的增加，架构对线程的支持也在增加。例如：

  • CPU 具有内核和硬件线程
  • Oracle SPARC T4 有 8 个内核，每个内核有 8 个硬件线程

11. 线程库

线程库为程序员提供创建和管理线程的 API。

11.1 两种主要实现方式

  • 用户级线程库：完全位于用户空间的库
  • 内核级线程库：操作系统支持的内核级库

12. Pthreads

12.1 概述

  • 用于线程创建和同步的 POSIX 标准（IEEE 1003.1c）API
  • 是规范，而非实现
  • API 规定了线程库的行为，实施则由开发库决定
  • 可作为用户级或内核级提供
  • 常见于 UNIX 操作系统（Solaris, Linux, Mac OS X）

13. 隐式线程

随着线程数量的增加而日益流行，显式线程更难保证程序的正确性。线程的创建和管理由编译器和运行时库而非程序员完成。

13.1 主要方法

  • 线程池
  • OpenMP
  • Grand Central Dispatch

其他方法包括 Intel 的线程构件（TBB）、java.util.concurrent 包等。

13.2 线程池

  • 在线程池中创建多个线程，让它们在池中等待工作
  • 优点：
    • 使用现有线程处理请求通常比创建新线程稍快一些
    • 允许应用程序中的线程数量与线程池的大小相匹配
    • 将要执行的任务与创建任务的机制分开，允许采用不同的策略运行任务
  • Windows API 支持线程池

13.3 OpenMP

  • 适用于 C、C++、FORTRAN 等语言的编译器指令集和应用程序接口
  • 为共享内存环境下的并行编程提供支持
  • 识别并行区域——可并行运行的代码块
  • 示例：
  • 创建与内核数量相同的线程

13.4 Grand Central Dispatch（GCD）

  • 适用于 Mac OS X 和 iOS 操作系统的苹果技术
  • 对 C、C++ 语言、API 和运行时库进行了扩展
  • 允许识别并行部分
  • 管理线程的大部分细节
  • 块位于 ^{ } 之内，例如：^{ printf("I am a block"); }
  • 块放入调度队列
    • 当块从队列中移出时，分配给线程池中可用的线程

13.5 GCD 队列类型

  • 串行队列：按先进先出顺序移除块，队列按进程排列，称为主队列。程序员可在程序中创建额外的串行队列
  • 并发队列：按先进先出顺序移除，但一次可移除多个区块。三个全系统队列，优先级分别为低、默认、高

14. 线程问题

14.1 fork() 和 exec() 的语义

  • fork() 只复制调用线程还是复制所有线程？
    • 某些 UNIX 有两个版本的 fork
  • exec() 通常正常工作
    • 替换正在运行的进程，包括所有线程

14.2 信号处理

  • UNIX 系统中使用信号来通知进程发生了特定事件
  • 信号处理程序用于处理信号
    • 信号由特定事件产生
    • 信号传递给进程
    • 信号由以下两种信号处理程序之一处理：默认处理程序；用户自定义处理程序
  • 每个信号都有默认处理程序，内核在处理信号时会运行默认处理程序
    • 用户定义的信号处理程序可以覆盖默认处理程序
    • 对于单线程，信号传递给进程

14.3 多线程信号处理

多线程信号应传递到哪里？

  • 向信号适用的线程发送信号
  • 向进程中的每个线程发送信号
  • 向进程中的特定线程发送信号
  • 指定一个特定线程接收进程的所有信号

相关函数：

  • kill(pid_t pid, int signal);
  • pthread_kill(pthread_t tid, int signal);

14.4 线程取消

  • 在线程结束前终止它
  • 要取消的线程是目标线程
  • 一般有两种方法：
    • 异步取消：立即终止目标线程
    • 延迟取消：允许目标线程定期检查它是否应该被取消

14.4.1 取消的实际行为

取决于线程状态：

  • 如果线程禁用了取消，取消将保持待定状态，直到线程启用它
  • 默认类型是延迟。只有当线程到达取消点（即 pthread_testcancel()）时，取消才会发生，然后调用清理处理程序
  • 在 Linux 系统中，线程取消是通过信号处理的

14.5 线程本地存储（TLS）

  • 线程本地存储允许每个线程拥有自己的数据副本
  • 在无法控制线程创建过程时（即使用线程池时）非常有用
  • 与局部变量不同，局部变量仅在单次函数调用时可见，TLS 在整个函数调用过程中都可见
  • 与静态数据类似，TLS 对每个线程都是唯一的

15. Linux 线程实现

  • Linux 将其称为任务而非线程
  • 线程的创建是通过 clone() 系统调用完成的
  • clone() 允许子任务共享父任务（进程）的地址空间，标志控制行为
  • struct task_struct 指向进程数据结构（共享或唯一）

16. 实践命令（Linux）

  • ps -ef | grep [进程名]：查看进程信息
  • top -p [pid]：查看特定进程的动态信息
  • top -H -p [pid]：查看特定进程的线程信息
  • ps xh：查看所有进程（无标题）
  • ps -mp [pid]：查看特定进程的线程详细信息

第四部分：调度（虚拟 CPU）

1. 调度概述

1.1 主题

调度包括两个方面：

  1. 如何从一个进程切换到另一个进程？
  2. 选择哪个进程来运行？
  • 机制：上下文切换（如何切换）
  • 机制：抢占（保持控制权）
  • 策略：调度（切换到哪里）

2. 调度机制

2.1 基本问题

内核如何从一个进程切换到另一个进程？

  • 系统有多个“就绪”进程
  • 为简单起见，我们假设只有一个 CPU

内核如何保持控制？

  • 进程可以 yield() 或执行 I/O
  • 可配置定时器中断，让操作系统控制进程

2.2 上下文切换

内核如何从一个进程 P 切换到另一个进程 Q？

  • 上下文切换在内核结构中保存当前运行进程 P 的状态
  • 上下文切换恢复进程 Q 的状态
  • 上下文切换将控制权转移到进程 Q 并返回

对进程而言，上下文切换是透明的

2.3 上下文切换的原因

  • 进程完成/退出
  • 进程执行缓慢的硬件操作（如从磁盘加载），操作系统切换到另一个就绪的任务
  • 硬件需要操作系统帮助并发出中断
  • 操作系统决定抢占任务并切换到另一个任务（即进程已用完其时间片）

2.4 上下文切换函数逻辑

  • 一次函数调用：进程 A 执行上下文切换，在 CS 函数返回后，进程 B 开始或继续执行
  • CS 函数会将所有寄存器保存在一个区域（进程内核堆栈或“进程控制块”的预定义区域）
  • 操作系统切换地址空间
  • CS 函数从上述区域恢复所有寄存器
  • 操作系统返回到进程 B，B 开始或继续执行

2.5 上下文切换示例（x86 汇编）

2.6 抢占

如果一个任务一直不放弃控制权（例如 yield()）、退出或执行 I/O，那么它就可以永远运行下去，操作系统也无法获得控制权。

解决方案：操作系统在调度进程前会设置一个定时器。如果计时器过期，硬件就会中断进程的执行并切换到内核。然后由内核决定进程是否可以继续。

3. 调度策略

3.1 定义

上下文切换机制负责内核从一个进程如何切换到另一个进程，即存储其上下文并恢复另一个进程的上下文。调度策略决定下一个应该运行哪个进程。

3.2 调度器指标

  • 利用率：CPU 执行程序的时间占多大比例（目标：最大化）
  • 周转时间：完成任务所需的总时间，( T_{completion} - T_{arrival} )（目标：最小化）
  • 响应时间：从作业到达到首次调度的时间，( T_{firstrun} - T_{arrival} )（目标：最小化）
  • 公平性：所有进程在一段时间内获得相同数量的 CPU（目标：不饥饿）
  • 进度：允许进程向前推进（目标：尽量减少内核中断）

3.3 进程状态回顾

3.4 调度器实现

最简单的形式：为每个状态，维护一个任务队列。

3.5 调度假设（简化）

为了逐步理解调度策略，我们从如下简单的假设开始：

  • 每个任务运行的时间相同
  • 所有工作在同一时间到达
  • 一旦启动，每个任务都要运行到完成
  • 所有任务只使用 CPU（无 I/O）
  • 任务的运行时间已知

4. 基本调度算法

4.1 先来先服务（FCFS/FIFO）

4.1.1 示例

  • 任务 A、B、C，长度=2，到达时间 T=0，简写为 (0,2)
  • 平均周转时间：(2+4+6)/3 = 4
  • 平均响应时间：(0+2+4)/3 = 2

4.1.2 特点

  • 简单、直接
  • 缺点：长任务会拖延短任务（车队效应）

4.1.3 车队效应示例

  • 任务 A 长度为 6，任务 B、C 长度为 2，同时到达
  • 平均周转时间：(6+8+10)/3 = 8
  • 平均响应时间：(0+6+8)/3 ≈ 4.7

4.2 最短工作优先（SJF）

4.2.1 原理

选择运行时间最短的就绪任务！

4.2.2 示例

  • 任务 A 长度为 6，任务 B、C 长度为 2，同时到达
  • 平均周转时间：(2+4+10)/3 ≈ 5.3
  • 平均响应时间：(0+2+4)/3 = 2

4.2.3 特点

  • 解决了长任务拖延短任务的问题
  • 但仍有车队效应：如果长任务先到达，短任务后到达，短任务仍需等待

4.2.4 SJF 车队效应示例

  • 任务 A (0,6)，任务 B、C (1,2)
  • 平均周转时间：(6+7+9)/3 ≈ 7.3
  • 平均响应时间：(0+5+7)/3 = 4

4.3 抢占式调度

4.3.1 非抢占式与抢占式

  • 非抢占式调度器：只有在当前进程自愿放弃 CPU 时，才会切换到另一个进程（如 FIFO、SJF）
  • 抢占式调度器：可以随时控制 CPU，并根据调度策略切换到另一个进程

4.3.2 最短完成时间优先（STCF）

总是运行最快完成的任务（考虑剩余时间）。

示例：任务 A (0,6)，任务 B、C (1,2)

  • 平均周转时间：(2+4+10)/3 ≈ 5.3
  • 平均响应时间：(0+0+2)/3 ≈ 0.7
  • 任务 A 在时间 1 被抢占！

4.4 响应时间优化

4.4.1 周转时间 vs 响应时间

  • 周转时间：完成任务所需的总时间
  • 响应时间：任务被调度所需的时间

4.4.2 示例

任务 A (0,2)，任务 B (1,1)

4.5 轮转调度（RR）

4.5.1 原理

每隔固定长度的时间片，交替调度就绪进程。

4.5.2 示例

  • 任务 A、B、C (0,3)，时间片=1
  • 平均响应时间：(0+1+2)/3 = 1
  • 平均周转时间：(7+8+9)/3 = 8
  • 对比 SJF：(3+6+9)/3 = 6

4.5.3 轮转调度的有效性

  • 任务数量：任务数量越多 → 响应时间越慢
  • 时间片长度：
    • 较长的时间片 → 较慢的响应时间
    • 较短的时间片 → 较多的开销
    • 10 毫秒到 100 毫秒通常是一个合理的折中值

4.6 考虑 I/O

  • 调度器必须考虑任务或进程的 I/O 时间
  • I/O 通常非常慢，可以异步执行

5. 高级调度算法

5.1 设计目标

设计一个调度器，既能为交互类任务最小化响应时间，又能最小化周转时间且无需知道任务运行时间。

5.2 多级反馈队列（MLFQ）

5.2.1 目标：通用调度

挑战：调度程序必须同时支持长时间运行的后台任务（批处理进程）和低延迟的前台任务（交互式进程）。

  • 批处理进程：响应时间并不重要，关心的是长时间运行
  • 交互式进程：响应时间至关重要，需要频繁的短时间交互
  • 由 Corbato 等人于 1962 年首次提出——他们后来获得了图灵奖

5.2.2 基本原理

方法：多级轮转

  • 优先级较高的进程抢占低级别的进程
  • 优先级较高的进程总是先被调度
  • 高优先级的进程时间片很短，低优先级的进程时间片较长

规则：

  1. 如果 prio(A) > prio(B)，则 A 运行
  2. 如果 prio(A) == prio(B)，则 A、B 以轮转方式运行
  3. 进程以最高优先级启动
  4. 如果进程用完了全部时间片，降低其优先级（考虑优先级的总时间）
  5. 定期将所有任务移至最上层队列（防止饥饿）

5.2.3 MLFQ 小结

  • 规则 1: 如果 prio(A) > prio(B)，则 A 运行
  • 规则 2: 如果 prio(A) == prio(B)，则 A、B 以轮转方式运行
  • 规则 3: 新进程以最高优先级启动
  • 规则 4: 当整个时间片被使用时，降低进程的优先级
  • 规则 5: 周期性地将所有任务移到最上面的队列中

5.3 完全公平调度程序（CFS）

5.3.1 理念

每个任务并行运行，消耗相同的 CPU 时间片。

5.3.2 示例

  • 单任务：100% CPU
  • 两个任务：50% CPU/任务
  • 四个任务：25% CPU/任务

5.3.3 虚拟运行时间

在实际 CPU 上，一次只能运行一个任务，因此引入“虚拟运行时间”的概念。

  • 任务的虚拟运行时间：指定了该任务在 CPU 上开始执行的下一个时间片
  • 任务的虚拟运行时间是其实际运行时间与运行任务总数的归一化
  • CFS 会记录每个进程在 CPU 上的运行时间
  • 对于每个时间片，它都会计算每个进程应获得的分数，并将这些分数保存在一棵树中
  • 然后对分数最高的进程进行调度

历史：Linux 曾使用基于多级反馈队列的 O(1) 调度器，但在 2007 年改用了完全公平的调度器 CFS

5.3.4 实现

  • 实现：将所有进程保存在一棵红黑树上，按最大执行时间排序
  • 调度过程：
    1. 调度最左边的进程
    2. 如果进程退出，则将其从调度树中移除
    3. 中断时（时间片结束或 I/O 结束），将进程重新插入调度树的新位置
    4. 重复上述操作

6. 总结

  • 上下文切换和抢占是基本机制，可让操作系统保持控制，并实施先进的调度策略
  • 调度器需要针对不同的指标进行优化：利用率、周转率、响应时间、公平性和前进速度
    • FIFO：简单、非抢占式调度器
    • SJF：非抢占式，防止进程堵塞
    • STCF：抢占式，防止后续进程堵塞
    • RR：抢占式，响应时间长，周转率低
    • MLFQ：抢占式，最现实
    • CFS：通过虚拟化时间实现公平调度
  • 过去的行为可以很好地预测未来的行为！
