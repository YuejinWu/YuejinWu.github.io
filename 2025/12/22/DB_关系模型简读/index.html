第一编：关系模型（Relational Model）【Chapter 2】

这是整个数据库理论的根基
👉 不懂这一章，SQL 永远是“背语法”

一、什么是关系数据库（Relational Database）

1️⃣ 为什么需要关系模型？

在关系模型之前：

  • 层次模型（树）
  • 网状模型（图）

👉 问题：

  • 数据结构复杂
  • 查询困难
  • 程序和数据强耦合

关系模型的革命性思想：

👉 用“数学集合 + 二维表”来抽象现实世界的数据

2️⃣ 关系数据库的基本组成

定义（直观）
一个关系数据库 = 若干张二维表（关系）

表元素 数学/理论名词 数据库名词
行 Tuple 元组
列 Attribute 属性
表 Relation 关系
表头 Schema 模式
表中数据 Instance 实例

二、关系模型的严格定义（Formal Definition）

这是考试最爱考定义的地方

1️⃣ 属性（Attribute）

  • 属性表示一个“对象的特征”

  • 用符号表示：

    A_1, A_2, \dots, A_n

📌 例子（instructor）：

  • ID
  • name
  • dept_name
  • salary

2️⃣ 域（Domain）

域 = 属性允许取值的集合

D_i = { 所有 A_i 可以取的合法值 }

📌 例：

  • ID ∈ char(5)
  • salary ∈ numeric(8,2)

⚠ 重要思想：

  • 域是类型 + 约束
  • 域 ≠ 属性名

3️⃣ 关系模式（Relation Schema）

描述“表长什么样”

形式化定义：

R = (A_1, A_2, \dots, A_n)

📌 instructor 模式：

4️⃣ 关系实例（Relation Instance）

描述“表里现在有什么数据”

  • 某一时刻关系中所有元组的集合
  • 随时间变化

📌 记忆口诀：

模式是蓝图，实例是照片

5️⃣ 元组（Tuple）

  • 一个元组 = 一行数据
  • 是属性 → 值的映射

数学上可理解为函数：

t(Ai)→Dit(A_i) \rightarrow D_i t(A​i​​)→D​i​​

三、属性的本质约束（非常重要）

1️⃣ 原子性（Atomicity）——第一范式（1NF）

每个属性值必须是“不可再分”的

❌ 错误示例：

✅ 正确做法：

📌 原因：

  • 保证运算有明确语义
  • 简化查询与比较

📌 考试常问：

“为什么关系模型要求 1NF？”

2️⃣ Null 值（Null）

Null ≠ 0
Null ≠ 空字符串

Null 表示：

  • 值未知
  • 值不存在
  • 尚未填写

⚠ Null 带来的三大问题（老师重点）

1️⃣ 比较失效

2️⃣ 三值逻辑（true / false / unknown）

3️⃣ 索引可能失效（工程大忌）

👉 工程建议：

  • 尽量用 default value 替代 null

四、关系的“无序性”（常被忽略但很重要）

1️⃣ 元组无序

  • 表中行没有先后顺序
  • 存储顺序 ≠ 逻辑顺序

2️⃣ 属性无序

(A1,A2,A3)=(A3,A1,A2)(A_1, A_2, A_3) = (A_3, A_1, A_2) (A​1​​,A​2​​,A​3​​)=(A​3​​,A​1​​,A​2​​)

👉 这就是为什么 SQL 必须写列名

五、数据库模式与实例（Schema vs Instance）

1️⃣ 数据库模式（Database Schema）

  • 全局逻辑结构
  • 不随时间变化

2️⃣ 数据库实例（Database Instance）

  • 某一时刻所有关系实例的集合
  • 会随插入、删除、更新变化

📌 考试爱问对比题

六、键（Keys）——关系模型的核心

1️⃣ 超键（Super Key）

能唯一标识元组的属性集合

形式化定义：

若

t1≠t2⇒t1[K]≠t2[K]t_1 \neq t_2 \Rightarrow t_1[K] \neq t_2[K] t​1​​≠t​2​​⇒t​1​​[K]≠t​2​​[K]

则 K 是超键

📌 示例：

  • {ID}
  • {ID, name}
  • {ID, dept_name}

⚠ 超键可能冗余

2️⃣ 候选键（Candidate Key）

最小的超键

  • 去掉任何属性就不唯一

📌 instructor：

  • {ID} ✔
  • {ID, name} ❌（非最小）

3️⃣ 主键（Primary Key）

从候选键中选一个作为“官方身份标识”

约束：

  • 唯一
  • 非空

📌 工程经验（老师强调）：

  • 尽量用 int / float
  • 避免 varchar / datetime

4️⃣ 主属性 & 非主属性

  • 主属性：出现在候选键中的属性
  • 非主属性：其余

📌 后续 函数依赖、范式分解 的基础

七、外键（Foreign Key）与参照完整性

1️⃣ 外键定义（极重要）

若：

  • r1 中属性 X
  • X 是 r2 的主键

则：

X 是 r1 引用 r2 的外键

2️⃣ 参照完整性（Referential Integrity）

外键值必须在被参照表中存在

📌 instructor.dept_name ∈ department.dept_name

3️⃣ 数据导入顺序（实践必考）

  1. 先插入被参照表（department）
  2. 再插入参照表（instructor）

否则违反外键约束

八、关系代数（Relational Algebra）

SQL 的数学基础

1️⃣ 查询语言分类

类型 特点
过程式 说明“怎么做”
声明式 说明“要什么”

关系代数 = 过程式
SQL = 声明式（但底层会转成代数）

2️⃣ 六个基本运算（必须会）

运算 符号 作用
选择 σ 行筛选
投影 π 列筛选
笛卡尔积 × 表组合
并 ∪ 合并
差 − 排除
重命名 ρ 改名

3️⃣ 选择（σ）

\sigma_{条件}(r)
  • 条件是布尔表达式
  • 支持：
    • 比较
    • 逻辑组合
    • 属性间比较

📌 SQL 对应：

4️⃣ 投影（π）

πA1,A2(r)\pi_{A_1,A_2}(r) π​A​1​​,A​2​​​​(r)

  • 只保留指定列
  • 自动去重

📌 SQL 对应：

5️⃣ 连接 = 笛卡尔积 + 选择

σr.A=s.B(r×s)\sigma_{r.A = s.B}(r \times s) σ​r.A=s.B​​(r×s)

👉 自然连接是语法糖

6️⃣ 查询等价与优化

  • 结果相同 ≠ 代价相同
  • 数据库会重写查询

📌 这是后面“查询优化”的起点
